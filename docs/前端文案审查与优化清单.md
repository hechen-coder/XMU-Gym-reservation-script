# 前端文案审查与优化清单

审查日期：2026-10-22。以下保留修改前的审查快照与行号；文案实施情况见文末“实施记录”。

## 范围与统计口径

覆盖预约大厅、未登录状态、独立登录页、定时预约、每周计划、余量监测、通知设置、预约记录、软件激活，以及接口返回到页面的状态和提示。另检查独立扫码工具和桌面托盘弹窗。

不把注释、文档、纯终端日志、变量名或接口名当作页面文案。`build/`、`dist/` 属于生成产物，不重复统计；社区版导出模板和 README 等说明材料不计入主页面数字。此次为源码审查，未启动预约、登录、发送邮件或实际预约验证。

下文归并为 **60 组优化项**。同一组可以涉及多个按钮、弹窗和状态；这不是 60 个词或 60 个页面。关键词表另按字面出现次数统计，同一句可以命中多个词，不能将命中次数理解为独立问题数量。

位置缩写（行号以此次审查时的工作区为准）：

- `T`：`xdty_booking/web/template.py`，预约大厅与主登录页。
- `W`：`xdty_booking/web/server.py`，页面接口与后台任务状态。
- `S`：`xdty_booking/core/scheduler.py`，定时任务回传的状态文案。
- `B`：`xdty_booking/core/booking_engine.py`，余量监测回传的状态与结果。
- `Q`：`cas_qr_login/server.py`，独立扫码工具页面。
- `L`：`packaging/launcher.py`，桌面启动器与托盘提示。

## 需要结合行为处理的地方

1. **余量监测并不等于“毫秒级锁定”。** 页面提供 1.5、2、3 秒间隔（T:1542—1544），接口接受 1—60 秒（W:955—956）。执行循环会在请求处理后等待设定间隔，并附加少量抖动（B:434—443）。因此不宜承诺精确每 N 秒完成一次检查，更不能把“发现名额”写成已锁定成功。检查间隔仍然可以如实显示。
2. **停止任务与取消成功预约要分开。** 此处停止接口停止本地后台任务（W:246—256、371—379），并未调用取消成功预约的接口。按钮应使用“停止定时任务”“停止余量监测”。进行中的请求不宜用文案保证能即时撤回。
3. **时间来自实际计划。** 定时任务支持自定义执行时间和每周计划，接口已经返回 `next_run_dt`（W:164）。启动成功提示和状态卡片可使用该字段，避免固定“明早 07:00”。说明中的 07:00 可以保留为默认示例。
4. **“相邻时段”与“按计划备选”是两种设置。** 单次任务可允许尝试相邻时段；每周计划按用户填写的最多三个优先级尝试。不能把两者都写成泛泛的“自动改约”，也不能让用户误以为会修改已经成功的预约。
5. **发送成功与提醒送达要分开。** 当前邮件实现以 SMTP 发送是否抛错判断发送结果（`xdty_booking/notify/notifier.py:124—136`），不能据此确认收件箱或微信弹窗已送达。微信设置入口本轮未做外部版本核验，建议实测后再给出具体路径。
6. **部分文案承载判断逻辑。** W:157、278 使用状态文字前缀判断任务状态；W:425、470 和 B:416 等按“登录、失效”等关键词识别错误。后续实施文案优化时，需检查这些依赖，避免直接全局替换破坏状态判断。变量名、API 路径、配置键和官方返回的原始错误不应跟随文案机械重命名。
7. **官方返回信息应保留证据。** 多处页面直接展示 `info`、`error`、`desc`、`status_text`。本项目能修改自己的提示；对外部返回信息，应保留原始结果用于排查，必要时增加友好的展示说明。本轮不将未知的官方返回文字算作已穷尽的自有文案。
