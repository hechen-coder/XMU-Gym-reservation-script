## 一、整体发布架构与流水线概览

本项目采用解耦且高度自动化的构建流程，实现了从 Python 源代码到免安装绿色包、安装向导包的全自动流水线：

```
源码与静态资产 (xdty_booking/ + packaging/)
    │
    ├── 1. 预构建安全混淆 (packaging/build_release.py ➔ protect_and_run_pyinstaller)
    │      └─ 调用 PyArmor 动态对 xdty_booking/security 实施防逆向混淆，构建后自动还原
    │
    ├── 2. 运行时入口适配器 (packaging/launcher.py)
    │      └─ 解决 exe 快捷方式工作路径漂移、双击无参交互菜单、自动唤醒浏览器
    │
    ├── 3. PyInstaller 核心编译 (packaging/XMU_Gym_Booking.spec)
    │      └─ 动态捕获 ddddocr ONNX 离线模型，剥离 Anaconda 数百兆无关冗余依赖
    │
    ├── 4. 绿色便携包组装与压缩 (dist/XMU_Gym_Booking_v1.0.0_Portable_Windows_x64.zip)
    │      └─ 拷贝配置文件模板、桌面快捷启动 bat、小白说明 txt，一键生成 ZIP
    │
    ├── 5. Inno Setup 安装包编译 (packaging/installer.iss)
    │      └─ 自动探测本地 ISCC.exe，输出标准 Windows 安装向导 (Setup.exe)
    │
    └── 6. GitHub Actions 云端流水线 (.github/workflows/release.yml)
           └─ Git 打 Tag 推送即可在微软云端 Windows 矩阵自动触发构建并发布 Release
```

## 二、本地一键构建实操指南

### 方式一：鼠标双击一键打包 (推荐)
在项目根目录下，直接双击运行：
👉 **`一键构建发布包.bat`** (或 `packaging/一键构建发布包.bat`)

脚本将自动检查依赖、清理旧缓存、编译可执行程序、组装绿色版、检测并编译 Inno Setup 安装包，并在控制台输出最终哈希清单。

### 方式二：终端命令行执行
在项目根目录打开 PowerShell / CMD，运行：
```bash
python packaging/build_release.py
```

构建完成后，所有最终交付物存放在项目根目录下的 **`dist/`** 目录：
- 📁 **`dist/XMU_Gym_Booking/`**：免安装解压即用程序目录；
- 📦 **`dist/XMU_Gym_Booking_v1.0.0_Portable_Windows_x64.zip`**：全功能绿色便携压缩包；
- 💿 **`dist/XMU_Gym_Booking_Setup_v1.0.0.exe`**：标准 Windows 安装向导 (需本地装有 Inno Setup)；
- 📝 **`dist/SHA256SUMS.txt`**：文件完整性哈希校验单。

## 三、Windows 原生安装向导制作 (Inno Setup)

本项目包含完整的安装向导构建脚本 `packaging/installer.iss`：

### 1. 功能特性
- 标准 Windows 向导界面，支持许可协议展示；
- 允许用户自定义安装路径，默认安装至 `%LOCALAPPDATA%\Programs\XMU_Gym_Booking`；
- 自动创建桌面图标、开始菜单快捷方式；
- 集成标准 Windows 控制面板卸载支持；
- 安装完成后支持勾选“立即启动网页预约控制台”。

### 2. 编译准备
1. 从官方免费下载安装 [Inno Setup 6 (isdl.php)](https://jrsoftware.org/isdl.php)；
2. 安装后将 `ISCC.exe` 所在目录（通常为 `C:\Program Files (x86)\Inno Setup 6`）添加到系统 `PATH` 环境变量；
3. 运行 `build_release.py`，构建脚本会自动探测到 `ISCC.exe` 并编译生成 `XMU_Gym_Booking_Setup_v1.0.0.exe`。

## 四、核心编译技术与难点排坑

### 1. `ddddocr` ONNX 离线模型丢失缺陷
- **问题根源**：`ddddocr` 内部通过 `os.path.join(os.path.dirname(__file__), 'common.onnx')` 动态查找模型文件，PyInstaller 默认不会自动收集扩展名为 `.onnx` 的非代码资源。
- **解决方案**：在 `packaging/XMU_Gym_Booking.spec` 中动态检测 `ddddocr` 安装路径，将 `common.onnx`、`common_det.onnx`、`common_old.onnx` 显式写入 PyInstaller 的 `datas` 映射清单。

### 2. 桌面快捷方式启动导致配置文件找不到
- **问题根源**：用户若将 exe 快捷方式复制到电脑桌面，双击启动时 Windows 默认会将当前工作目录置为用户桌面，导致程序寻找 `./config/config.yaml` 报 `FileNotFoundError`。
- **解决方案**：在 `packaging/launcher.py` 初始化阶段判断 `sys.frozen`，若为打包模式，强制调用 `os.chdir(os.path.dirname(sys.executable))` 将运行路径重置为程序所在的真实绝对路径。

### 3. 直接双击闪退与无参数引导
- **问题根源**：原生 `main.py` 要求必须附带子命令（如 `main.py web`），普通用户直接双击 exe 会因 `args` 为空退出。
- **解决方案**：`packaging/launcher.py` 智能拦截空参数启动，自动呈现带数字选项的交互式控制台菜单，默认选项为 `1` 并自动调起默认浏览器打开 `http://localhost:8080`。

## 五、PyArmor 源码安全混淆保护机制

为了防止打包生成的 EXE 被 `pyinstaller-extractor` / `uncompyle6` / `pycdc` 轻易还原出明文逻辑，流水线设计了动静态无缝结合的混淆防护方案：

1. **混淆拦截时机**：在 `packaging/build_release.py` 的 `protect_and_run_pyinstaller()` 中执行；
2. **源码临时备份**：将 `xdty_booking/security` 完整暂存至 `xdty_booking/security_source_backup`；
3. **动态混淆注入**：调用 `pyarmor gen -O build/obf_sec xdty_booking/security` 生成高强度混淆字节码；
4. **编译与还原**：PyInstaller 编译提取混淆后的保护层，编译完成无论成功失败，通过 `finally` 块 100% 自动无损还原本地 Python 源码，不污染 Git 工作区。

## 六、GitHub Actions 自动化云端流水线

无需在本地占用电脑配置进行编译，可直接借力 GitHub Actions 云端构建：

1. **触发方式**：向远程仓库推送符合语义化版本格式的 Tag（例如 `v1.0.0`）：
   ```bash
   git tag v1.0.0
   git push origin v1.0.0
   ```
2. **云端流水线执行流程 (`.github/workflows/release.yml`)**：
   - 调度微软官方 `windows-latest` 纯净虚拟机；
   - 自动检出代码、配置 Python 3.8 ~ 3.11 生产环境；
   - 利用 Chocolatey 自动无感安装 Inno Setup 编译器；
   - 执行 `python packaging/build_release.py` 编译全部制品；
   - 计算 SHA-256 校验和并自动创建 GitHub Release，将安装包与绿色 ZIP 挂载为 Release 资源供所有人下载。
