# 打包与发布部署指南

更新日期：2026-10-22。此指南描述当前代码提供的构建流程；干净机器上的窗口、组件安装与升级验收仍须执行。

## 1. 发布形式与旧产物保护

同一个 Release 提供便携 ZIP 和安装版 Setup.exe，使用同一应用构建、相同功能。ZIP 内主程序是 onedir 启动器，依赖 `_internal` 等资源，不能单独复制出去。Setup.exe 是安装向导，不是另一个独立单文件主程序。

新构建写入：

```text
dist/releases/v1.2.3/<UTC时间>-<随机批次>/
  XMU_Gym_Booking/
  XMU_Gym_Booking_v1.2.3_Portable_Windows_x64.zip
  XMU_Gym_Booking_Setup_v1.2.3.exe
  SHA256SUMS.txt
  release-notes.md
  self-test.json
```

现有 `dist/XMU_Gym_Booking`、所有历史 ZIP、历史校验和均不清理、不覆盖。新目录存在 `BUILD_INCOMPLETE` 表示构建未完成，不得发布。没有“清空 dist”步骤，也不会按进程名结束用户的应用。

版本来源为 `packaging/version.json`，可通过 `--version` 显式覆盖；ZIP、Setup、EXE 版本资源和 build-info 使用相同值。同版本重复构建仍写入不同批次目录。

## 2. 准备环境

- 使用 Python 3.8 x64，保持当前解释器路线。
- 依赖版本基线见 `packaging/constraints-python38.txt`。它约束直接依赖，不代表已经交付完整的离线 wheel 集合；干净环境的重新安装仍需验证传递依赖。
- 安装 Inno Setup 6；支持当前本机 `D:\Inno Setup 6\ISCC.exe`，其他目录使用 `--iscc` 指定。
- 从 [微软官方 WebView2 下载页](https://developer.microsoft.com/en-us/microsoft-edge/webview2/) 获取约 2 MB 的 Evergreen Bootstrapper。
- 引导安装器默认放在 `packaging/prerequisites/MicrosoftEdgeWebview2Setup.exe`，也可指定已有路径。不将安装器二进制提交到 Git。缺失 Runtime 时需要联网下载完整组件；无需把 200 多 MB 的完整离线安装器装进每个发布包。
- 正式构建使用 PyArmor，混淆失败会停止。试用授权的大小限制也会导致构建失败，不自动转成明文版。

构建器不会自动修改依赖或升级 Python。除检查包版本，还会在子进程加载 CLR、ONNX、ddddocr 和 cryptography OpenSSL backend，阻止原生 DLL 无法加载的环境进入正式构建。

已确认激活 Conda base 后，OpenSSL 输出 `OpenSSL 1.1.1k 25 Mar 2021`，完整预检通过。此前失败发生在未激活的子进程环境中，无需因此升级 Python 或重装 cryptography。请在同一个已激活终端执行预检和构建。

## 3. 构建命令

在项目根目录运行：

```powershell
conda activate base
python packaging/build_release.py --check --runtime-installer "D:\Downloads\MicrosoftEdgeWebview2Setup.exe" --iscc "D:\Inno Setup 6\ISCC.exe"
python packaging/build_release.py --runtime-installer "D:\Downloads\MicrosoftEdgeWebview2Setup.exe" --iscc "D:\Inno Setup 6\ISCC.exe"
```

如果安装器已放到默认目录，可省略 `--runtime-installer`。

可选参数：

| 参数 | 用途 |
| --- | --- |
| `--version 1.2.3` | 覆盖本次版本，不覆盖历史批次 |
| `--iscc "D:\Inno Setup 6\ISCC.exe"` | 显式指定带空格目录中的 Inno Setup 编译器 |
| `--check` | 只验证前置条件，不创建发布目录 |
| `--portable-only` | 显式只构建 ZIP，用于开发验证；不是完整双制品发布 |
| `--no-obfuscation` | 显式关闭混淆的诊断构建，build-info 会记录 |

默认要求具备 Setup 编译器和有效的微软 Bootstrapper。缺少任一条件时停止；不会宣称两种制品已经全部生成。

## 4. 隔离、模型和文件检查

构建器将所需 Python 源码、配置示例、spec、hook、图标和 manifest 复制到全新 staging，在其中混淆和打包。不会临时删除、替换开发目录的安全模块。

模型保持 ddddocr 已验证分类路径所需的 `common_old.onnx`。WebView2 应用侧 DLL 与对应 x64 Loader 按库目录布局收集，不靠跨架构路径回退。压缩暂关闭 UPX，以减少未验证的压缩变量。

最终目录附带配置示例、图标、用户说明、LICENSE、官方 Runtime 安装器、build-info 和文件哈希清单。真实配置、会话、授权、日志和私钥会被拒绝进入发布目录；certifi 的公开 CA 文件按明确路径允许。

## 5. 真实冻结产物自检

构建器将新应用复制到本轮工作目录，再调用：

```powershell
.\XMU_Gym_Booking.exe self-test --output "D:\自检结果\self-test.json"
```

输出目录需要已存在。自检实际加载 cryptography、执行 ONNX OCR 推理、检查授权公钥模块，并启动回环 HTTP 做当前实例健康检查；不访问学校接口、不尝试预约、不采集硬件指纹、不自动安装 Runtime。

测试使用副本，首次运行产生的配置和日志不会混入公开 ZIP。报告记录每项结果；失败或超时阻止归档。通过自检也不等于 GUI、Runtime 安装及 PyArmor 在其他机器上的验收已经完成。

## 6. 用户启动与组件修复

默认启动独立应用窗口。HTTP 服务不做主机名反向解析，支持中文电脑名；确认健康响应属于当前实例后才打开界面。桌面默认端口占用时可以使用实际分配的其他端口；显式 CLI 端口失败则准确报错。

缺少 WebView2 Runtime 或窗口初始化失败时，提供不依赖 WebView2 的原生修复窗口：安装或修复、重试、退出，以及主动选择的应急浏览器入口。不会自动打开默认浏览器。安装后受控重启，限制重试次数。

修复前检查 Bootstrapper 的微软 Authenticode 签名。便携应用本体无需安装，但缺少 Runtime 时仍需确认联网安装该系统组件；网络、组织策略或权限可能阻止安装。Setup 在安装阶段检测并处理 Runtime，桌面快捷方式默认进入应用模式。完整离线安装器可单独保留，作为网络受限时的手动修复资源。

源码 `main.py web` 保持 CLI 服务入口。冻结应用显式 `web --port 端口` 或修复窗口主动选择应急模式，才会打开浏览器；浏览器页面关闭不会停止后台任务，原生控制提示提供退出入口。

## 7. 数据、日志与退出

便携版保留解压目录下的数据位置。Setup 写入 `installed-mode` 标记，安装版用户数据位于 `%LOCALAPPDATA%\XMU_Gym_Booking`，应用资源位于安装目录。首次迁移只复制缺少的旧配置、授权和状态文件，不覆盖已存在用户数据，也不删除源文件。

启动诊断写入 `logs/startup.log`，GUI 兼容日志写入 `logs/gui_error.log`，业务日志写入 `logs/booking.log`；启动和业务日志使用轮转。发送诊断前需脱敏，不发送原始登录信息或授权文件。

退出时停止调度、捡漏和心跳，关闭本地服务和窗口，释放互斥体。托盘创建失败时保持可见窗口，不让应用消失到无法恢复的位置。

## 8. 发布验收与上传

1. 检查构建完成标记、self-test 报告、版本和文件清单。
2. 分别从干净系统快照验证 ZIP 和 Setup；前一个测试安装的 Runtime 不能掩盖后一个制品的问题。
3. 覆盖中文电脑名、中文路径、无 Python、无 Runtime、普通用户、端口占用、首次安装、取消安装、窗口加载失败和退出重启。
4. 检查既有配置、授权和防回拨状态在升级后保留，运行任务和托盘恢复正常。
5. 通过后再将本批次 ZIP、Setup、SHA256SUMS、release-notes 上传到同一 Release；不要额外上传包内裸主程序 EXE。

当前不假定项目存在可用的 GitHub Actions 发布流水线。脚本只本地生成制品，不创建 Tag、不上传、不自动发布。
